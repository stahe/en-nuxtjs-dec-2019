    5. Example [nuxt-02]: server and client pages

    In this project, we demonstrate:

    • that the page built by the client may look different from the one received from the server. This results in a rapid page change that the user notices, which is detrimental to the application’s usability. This is therefore a option to avoid;
    • a solution for the client page to recreate the same page as the one sent by the server;

    The [nuxt-02] project is initially obtained by cloning the [nuxt-01] project.

    A folder named [store] is added to the project, along with two new pages. We will return to this later.

    5.1. The [index] page

    5.1.1. The page code

    5.2. The page [page1]

    5.2.1. The [Vuex] store

    We added a folder named [store] to the [nuxt-02] project:

    The presence of this folder causes [nuxt] to automatically implement a store named [Vuex]. The file [index.js] implements this store. Here, the file [index.js] is as follows:

    
export const state = () => ({
  counter: 0
})
 
export const mutations = {
  increment(state, inc) {
    state.counter += inc
  }
}

    [nuxt] implements a store [Vuex] based on the contents of [index.js]:

    • lines 1–3: definition of the store’s state [state]. This state is returned by a function. Here, the state has only one property, the counter in line 2. The exported function must be named [state];
    • lines 5–9: the operations possible on the store state. These are called [mutations]. Here, the [increment] mutation increments the [counter] property by an amount of [inc]. The exported object must be named [mutations];

    The [store] View implemented by [nuxt] is available in various locations. In views, it is available in the [this.$store] property.

    5.2.2. The page code

    Like the [index] page, the [page1] page will display a value, that of the Vuex store counter:

    • the client-side scripts embedded in the sent page take over and execute the page [page1.vue] again;

    • Lines 12–26 are not executed by the client because the condition [process.server] on line 12 is false. Therefore, the counter in the store [Vuex] is 0 (its initial value in the store), and this is the value displayed on the page;

    One might wonder what happens when we comment out [if] in lines 12 and 26. Here is the answer:

    • This time, the client executes lines 14–25, but [nuxt] does not wait for the asynchronous function to finish (as the server does) and therefore leaves the counter at 0;
    • after 10 seconds, the asynchronous function completes and the counter is set to 52 on line 23;
    • when navigating back to the [page4] page, the value 52 is then displayed;

    5.7. Summary

    From our various tests, we note the following points:

    • if the page [index] is to contain external data, this data can be retrieved by the server using the function [asyncData];
    • if the server needs to initialize a [Vuex] store with external data when loading the [index] page, it will do so in the [fetch] function;
    • the page generated by the server and the page generated by the client must be identical to avoid the "jumping" effect caused by the client's page visually replacing the page sent by the server and initially displayed;
